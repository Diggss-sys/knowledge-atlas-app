Knowledge Atlas Team Hub

Windows-first: stabilize the demo, then widen delivery.

Milestone: M2 Primary platform: Windows Updated: 2026-07-24

1. The current pivot

Windows is the primary demo path. Diego's realism work and the operator-to-participant flow are integrated on main.

We are no longer trying to optimize two platforms while the visual target is moving. The immediate goal is one convincing, correct local Windows demo. Mac native delivery is deferred, not abandoned.

  • Do not start new Mac builds, Mac performance tests, or Mac release work.
  • Do not start formal pilot sessions yet.
  • Do verify Windows fidelity, runtime experiment correctness, the full author-to-CSV flow, and demo-PC performance.

2. Windows acceptance checklist

  1. Runtime pair-gate parity: the live gate must enforce the same single-variable rule as the validator.
  2. Visual smoke: inspect the current HDRP room, curved walls, openings, lighting, materials, and furniture on the Windows demo machine.
  3. Full product smoke: author - validate - publish - participant - CSV.
  4. Performance: measure the Windows demo PC against the 60 FPS target and note visible hitches.
  5. Fidelity verdict: the study/fidelity reviewer calls pass, conditional pass, or fail from current screenshots/video.
Important: a clean local Windows workspace should be used for this work. The older UI checkout contains parked Mac work and untracked Unity assets that can collide with tracked editor settings.

3. Team roles - claim a lane

Diego (Windows engine and contracts)

  • Own geometry, HDRP/lighting realism, and runtime pair-gate correctness.
  • Provide the Windows visual smoke and identify the next fidelity improvement only after it is clean.

Paco + Claude (Windows integration)

  • Work from the clean main baseline.
  • Verify author - publish - participant - CSV and record Windows demo-PC performance.
  • Keep the local Mac packaging fix parked while Windows is the priority.

Study + fidelity review (no-code role)

  • Choose the demo experiment, hypothesis, rating prompt, and participant instructions.
  • Review Windows screenshots/video and give a pass, conditional-pass, or fail verdict.

Access + streaming (Mac-team role)

  • After the local Windows smoke passes, prove a Mac can use the Windows PC as a GPU host with clear video, responsive input, and simple same-network setup.
  • Research hourly cloud GPU only if the self-hosted Windows-PC route is insufficient.

4. Delivery path

Demo now: run locally on the Windows GPU PC. This is the lowest-risk way to show the finished product.

Next delivery experiment: let a Mac connect to that Windows PC and stream the app's display/input over the local network. The Unity app remains a Windows app; the Mac is the client.

Later fallback: hourly cloud GPU hosting, only if the self-hosted Windows PC cannot provide the access the team needs.

Mac native app

Deferred. The current Mac release has a packaging defect and below-target performance. The packaging repair is preserved as parked work; do not ask teammates to run new Mac tests during this phase.
